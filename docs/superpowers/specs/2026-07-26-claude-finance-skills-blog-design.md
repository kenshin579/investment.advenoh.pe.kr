# Claude 금융 스킬 블로그 시리즈 설계

- 작성일: 2026-07-26
- 상태: 설계 확정
- 산출물: 블로그 글 3편 (`contents/etc/` 1편, `contents/stock/` 2편)

## 1. 배경과 목적

Anthropic이 공개한 `anthropics/financial-services` 마켓플레이스에는 21개 플러그인, 100개 이상의 금융 스킬이 들어 있다. 이 도구를 개인 투자자가 실제로 어디까지 쓸 수 있는지 정리하고, 직접 돌린 결과물을 함께 공개한다.

핵심 질문은 두 가지다.

1. 유료 데이터 구독(FactSet, Capital IQ, Daloopa) 없이도 쓸 만한가
2. 스킬이 뽑아준 리포트를 어디까지 믿을 수 있는가

## 2. 독자

Claude Code를 이미 사용 중인 개발자 겸 투자자. 설치 과정은 명령어 수준으로 압축하고, 지면은 스킬의 실제 산출물과 한계에 집중한다.

터미널 사용 경험이 없는 일반 투자자는 대상이 아니다. Claude Code 설치 가이드는 이미 충분히 많고, 그쪽으로 가면 이 글만의 각도가 사라진다.

## 3. 글 구성

3편을 `series: "Claude 금융 스킬"`로 묶는다.

| | 글 1 | 글 2 | 글 3 |
|---|---|---|---|
| 카테고리 | `etc` | `stock` | `stock` |
| slug | `claude-code-finance-skills-guide` | `us-semiconductor-sector-overview` | `alphabet-comps-analysis` |
| 성격 | 도구 가이드 | 섹터 리서치 | 종목 분석 |
| 사용 스킬 | 전체 소개 | `equity-research:sector-overview` | `financial-analysis:comps-analysis` |
| 주제 | 설치 · 사용법 · 검증법 | 미국 반도체 섹터 | 구글 피어 비교 |
| 검색 타깃 | "Claude Code 금융 스킬" | "미국 반도체 섹터 전망" | "구글 주가 밸류에이션" |
| 분량 | 약 12,000자 | 실행 후 결정 | 실행 후 결정 |

글 2와 3의 분량은 미리 정하지 않는다. 스킬을 실제로 돌려보고 산출물이 나온 뒤에 결정한다. 목표 글자 수를 먼저 잡으면 내용을 채우려고 산출물을 부풀리게 되는데, 이 두 글은 스킬이 실제로 뽑아낸 만큼만 보여주는 것이 목적이다.

### 3.1 역할 분담

글 1은 도구 가이드다. 검증 방법론을 여기에만 두고, 글 2와 3은 검증 **결과**만 싣고 방법론은 글 1로 링크한다. 같은 내용을 세 번 쓰는 것을 막기 위한 장치다.

글 2와 3은 스킬 산출물 쇼케이스다. 스킬이 생성한 초안을 검증·보완한 최종본을 싣고, 상단 고지 블록으로 출처를 명시한다.

### 3.2 제작 순서

글 2 → 글 3 → 글 1 순으로 만든다.

실제로 스킬을 돌려봐야 글 1에 쓸 재료(무엇이 막히는지, 토큰이 얼마나 드는지, 어떤 항목에서 환각이 나는지)가 나온다. 글 1을 먼저 쓰면 스킬 목록 나열에 그친다.

## 5. 글 2 — 반도체 섹터 리포트 검증

카테고리 `stock`, slug `us-semiconductor-sector-overview`.

### 5.1 설계 변경 (2026-07-26, Task 2 완료 후)

당초 설계는 "섹터 리포트를 싣고 말미에 검증 결과를 덧붙인다"였다. Task 2 검증 결과에 따라 **검증을 본론으로, 섹터 내용을 근거로** 재배치한다.

검증 결과는 62개 항목 중 일치 31 / 근사 2 / 불일치 15 / 출처확인불가 14였고, UNSOURCED 11건을 더해 제외 대상이 40건이다. 이 중 5건은 `raw.md`에 값이 없던 누락 항목이라 실제로 걷어낼 값은 35건이다.

제외 항목이 2차·3차 웹 출처 구간에 몰려 있어, 남은 것으로 온전한 섹터 리포트를 표방하면 독자가 이를 검증된 전망으로 오해한다.

변경의 근거는 셋이다.

1. **정직성** — 제외 40건을 걷어내고 리포트 형식을 유지하면, 말미의 경고가 본문 형식에 묻힌다
2. **수명** — "2026년 7월 반도체 전망"은 반년이면 낡지만 "어떤 종류의 수치가 왜 틀리는가"는 낡지 않는다
3. **독자 적합성** — 이 시리즈의 독자는 Claude Code를 쓰는 개발자 겸 투자자다. 도구의 신뢰 한계가 섹터 전망보다 값지다

다만 섹터 내용을 버리는 것은 아니다. WSTS 원문 11개 수치, SIA 릴리스, TrendForce Q4 2025, TSMC 6-K, EDGAR 재무 14개사는 검증을 통과했다. 이들은 "검증된 사실"로 본문에 남는다.

### 5.2 목차

`### 2.2.2` 밸류체인은 Mermaid `graph LR`로 그린다. 설계 - 파운드리 - 후공정 - 장비 흐름. 산출물 원본은 ASCII art이므로 반드시 변환한다.

`# 1`에는 실행한 명령어, 넣어준 입력, 걸린 시간, 산출물 형태를 짧게 적는다.

`# 2.2`에는 **검증을 통과한 수치만** 싣는다. 제외 목록 40건은 하나도 넣지 않는다. 검증 문서 `§10.0`이 쓸 수 있는 것을 구간별로 정리해두었으므로 62행 표를 직접 훑지 않는다.

`# 4`가 이 글의 핵심이다. Task 2에서 나온 세 가지 실패 유형을 사례로 다룬다.

`# 6`은 종합 평가다. 검증 *방법론*은 설명하지 말고 글 1로 링크한다.

피어 그룹은 하이퍼스케일러 묶음으로 잡는다. MSFT, AMZN, META를 주 비교군으로 하고 AAPL을 참고로 붙인다. 광고 묶음은 표본이 얇고, 빅테크 7 전체는 애플과 테슬라가 섞여 비교가 흐려진다. 하이퍼스케일러 묶음은 글 2의 AI 가속기 수요처 이야기와 이어져 시리즈가 하나로 묶인다.

구글은 반도체 섹터가 아니므로 글 2와 글 3은 독립적인 사례다. 다만 구글이 브로드컴과 TPU를 공동 설계하는 지점을 서사적 연결 고리로 쓴다.

### 6.1 목차 확정 시점

글 2가 5.1의 이유로 검증 중심으로 재배치됐다. 글 3도 같은 방향으로 갈 가능성이 높지만, **Task 5 검증 결과를 보고 정한다.**

두 스킬의 성격이 다르기 때문이다. `sector-overview`는 시장 규모·점유율처럼 공시에 없는 항목이 많아 2차 웹 출처 의존도가 높았다. `comps-analysis`는 재무 지표와 멀티플이 중심이라 EDGAR로 대부분 확인 가능할 수 있다. 그렇다면 검증 통과율이 훨씬 높게 나오고, 글 3은 원래 설계대로 피어 비교 분석 자체를 본론으로 삼는 것이 맞다.

Task 5 완료 후 검증 통과율을 보고 결정한다. 통과율이 높으면 원래 설계(피어 비교가 본론), 낮으면 글 2와 같은 구조(검증이 본론)로 간다.

## 8. 데이터 조달 방식

유료 MCP 커넥터는 사용하지 않는다. 대신 아래를 쓴다.

- SEC EDGAR — 10-K/10-Q 원문 및 XBRL 재무 데이터 (무료)
- 각 사 IR 페이지 — 실적 발표 자료
- WebSearch / WebFetch — 시장 규모, 점유율, 컨센서스 등 공시에 없는 항목

**모든 수치는 출처를 명시하고 원문과 대조한다.** 대조하지 못한 항목은 글에 싣지 않거나, 출처 불명임을 명시한다. 투자 블로그에 검증되지 않은 재무 수치를 싣는 것은 신뢰도 문제로 직결된다.

## 9. 공통 작성 규칙

프로젝트 `CLAUDE.md` 규칙을 그대로 따른다.

- 이모지 사용 금지
- 다이어그램은 ASCII 금지, Mermaid만 사용
- 목차 번호 체계: `# N.` / `## N.M` / `### N.M.K`
- 마지막 본문 섹션은 "정리"가 아닌 "마무리"
- frontmatter에 `series: "Claude 금융 스킬"` 지정
- 모든 파일 UTF-8 인코딩

글 2와 3은 시간이 지나면 낡는다. 서두에 데이터 기준일을 명시하고, 갱신 시 frontmatter `update` 필드를 올린다.

### 9.1 humanizer 미적용

이 시리즈에는 `k:humanizer` 스킬을 적용하지 않는다.

글 2와 3은 상단 고지 블록으로 "이 글은 스킬이 생성한 결과물"임을 명시하는 글이다. 그런 글의 문체를 사람이 쓴 것처럼 다듬는 것은 글의 취지와 충돌한다. 독자가 스킬의 실제 출력 품질을 판단할 수 있어야 하므로 원본 톤을 유지한다.

글 1도 같은 방침을 따른다. 다만 이모지 금지 등 `CLAUDE.md`의 다른 작성 규칙은 3편 모두 그대로 적용한다.

## 10. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| AI가 생성한 재무 수치의 환각 | 모든 숫자를 SEC 원문과 대조, 대조 실패 항목은 제외 |
| 독자가 투자 판단 근거로 오해 | 상단 고지 블록에 명시, `# 7` 검증 섹션 유지 |
| AI 티가 나는 문체 | 시리즈 전체에 `k:humanizer`를 적용하지 않는다 (9.1 참조) |
| 검증 섹션이 3편에 중복 | 방법론은 글 1에만, 글 2·3은 결과 표만 |
| 시간이 지나 데이터가 낡음 | 기준일 명시, `update` 필드 관리 |

## 11. 완료 기준

- 글 3편이 `contents/`에 위치하고 `npm run build`가 통과한다
- 모든 재무 수치에 출처가 달려 있다
- 이모지가 없고 다이어그램이 Mermaid로 렌더링된다
- 목차 번호 체계가 `content-heading-style` 규칙에 맞는다
- `npm run start` 후 3편 모두 정상 렌더링된다
