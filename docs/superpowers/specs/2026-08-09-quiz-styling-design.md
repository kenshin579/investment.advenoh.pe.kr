# 퀴즈 스타일 개선 설계

- 작성일: 2026-08-09
- 대상 저장소: `investment.advenoh.pe.kr`
- 선행 문서: `docs/superpowers/specs/2026-08-09-quiz-design.md` (퀴즈 기능 자체의 설계)

## 1. 문제

배포된 퀴즈가 온통 회색으로 보이고 글자가 고정폭이다. 색을 잘못 고른 것이 아니라 **버그**다.

배포 페이지에서 측정한 계산된 스타일:

```
coloredAncestors: [
  { tag: "PRE", bg: "rgb(245, 245, 244)" },
  { tag: "ARTICLE", bg: "rgb(255, 255, 255)" }
]
font: "ui-monospace"
```

`react-markdown` 은 펜스 코드 블록을 `<pre><code>` 로 렌더한다. `markdown-renderer.tsx` 는 `code` 만 가로채 `<Quiz>` 를 반환하는데 **바깥 `<pre>` 가 그대로 남는다.** 거기에 두 가지가 걸린다.

- `globals.css` 의 `.markdown-content pre { @apply bg-muted p-4 rounded-lg overflow-x-auto; }` → 회색 배경
- `pre` 의 브라우저 기본 `font-family: monospace` → 퀴즈 안 모든 글자가 고정폭

선행 설계 문서 6절 "스타일 격리"는 `not-prose` 로 충분하다고 적었는데 틀렸다. `not-prose` 는 Typography 플러그인이 주는 스타일만 끊고, **퀴즈가 `<pre>` 안에 들어 있다는 사실 자체**는 건드리지 못한다. 구현 중 브라우저 검증에서 기능(렌더·채점·앵커)만 확인하고 상속되는 스타일을 보지 않아 놓쳤다.

### 부수 확인

같은 글의 `<pre>` 5개가 전부 회색이었고 그중 **4개가 mermaid 다이어그램**이다. 즉 이 블로그의 모든 다이어그램도 코드 블록 배경 위에 그려지고 있다. **이번 작업에서는 고치지 않는다** — 글 113편의 다이어그램 모양이 한꺼번에 바뀌는 변경이라 별도 판단이 필요하다.

## 2. 범위

### 포함

- 퀴즈에 한해 `<pre>` 껍데기 제거
- 퀴즈 섹션에 옅은 파랑 틴트 배경과 테두리 (구간 구분)
- 다크 모드에서 문항 카드 배경 명시
- 보기 버튼 hover 색

### 제외

- **mermaid** — 지금 모습 유지 (1절 부수 확인 참조)
- **일반 코드 블록** — 지금 경로 유지
- **`--accent` 토큰 수정** — 아래 4절 참조
- 정답/오답 초록·빨강, 접근성 처리(`aria-disabled`, `sr-only`, `readOnly`), 앵커 스크롤, 채점 로직 — 전부 그대로

## 3. `<pre>` 껍데기 제거

`markdown-renderer.tsx` 의 `components` 맵에 `pre` 핸들러를 추가한다. **자식이 `language-quiz` 인 경우에만** 래퍼 없이 자식을 그대로 렌더하고, 그 외에는 기본 `<pre>` 를 유지한다.

퀴즈만 조건부로 벗기는 이유: 무조건 벗기면 mermaid와 일반 코드 블록까지 영향을 받는다. 전자는 이번 범위에서 뺐고, 후자는 `SyntaxHighlighter` 가 `PreTag="div"` 로 자기 컨테이너를 만들지만 언어 없는 펜스(` ``` ` 만 쓴 경우)는 컨테이너 없이 남는다.

## 4. 시각 설계

선택안: **섹션 틴트** (목업 3안 중 B).

### 토큰

| 대상 | 라이트 | 다크 |
|------|--------|------|
| 섹션 배경 | `rgba(32,148,243,.045)` | `rgba(32,148,243,.07)` |
| 섹션 테두리 | `rgba(32,148,243,.18)` | `rgba(32,148,243,.25)` |
| 문항 카드 배경 | 페이지 배경색 | 페이지 배경색 |
| 보기 hover | primary 테두리 + `primary/5` 배경 | 동일 |

`32,148,243` 은 `--primary: hsl(207, 90%, 54%)` 를 RGB로 옮긴 값이다.

다크의 농도가 라이트보다 진한 이유: 배경이 어두워 같은 알파로는 틴트가 보이지 않는다.

**문항 카드 배경은 라이트에서도 명시해야 한다.** 현재 카드에는 배경 클래스가 아예 없어(`rounded-lg border border-border p-5`) 투명이다. 지금은 페이지가 흰색이라 흰 카드처럼 보이지만, 섹션에 틴트를 깔면 그 틴트가 카드 안까지 그대로 비친다. 라이트·다크 모두 페이지 배경색을 명시한다.

### 다크 모드 카드 배경을 명시하는 이유

이 저장소는 다크 팔레트에서 `--card` 와 `--background` 가 **둘 다 `hsl(240, 10%, 3.9%)` 로 같은 값**이다. 따라서 문항 카드에 `bg-card` 를 주면 다크에서는 배경이 없는 것과 같아져 섹션 틴트가 카드 안까지 그대로 비친다. 카드에 페이지 배경색을 명시해 틴트 면보다 카드가 더 어둡게 파이도록 한다. 라이트에서는 반대로 카드가 더 밝다.

### hover 색을 퀴즈 안에서만 처리하는 이유

현재 보기 버튼은 `hover:bg-accent hover:text-accent-foreground` 를 쓰는데, 이 저장소는 **`--accent` 와 `--muted` 가 같은 값**이라(`hsl(60, 4.8%, 95.9%)`) 마우스를 올려도 사실상 아무 변화가 없다. 누를 수 있는 요소로 보이지 않는다.

근본 원인은 `--accent` 토큰이지만 그것을 고치면 이 토큰을 쓰는 **사이트 전역**(shadcn 컴포넌트 다수)의 hover가 한꺼번에 바뀐다. 이번 작업은 퀴즈를 고치는 것이므로 퀴즈 버튼에 직접 색을 지정한다. 토큰 수정은 사이트 전체를 다시 훑어야 하는 별도 과제로 남긴다.

답한 뒤에는 hover가 걸리지 않아야 한다. 현재 코드가 `!done && 'hover:...'` 로 이미 처리하고 있으므로 그 구조를 유지한다.

## 5. 함께 고친 것 — 앵커 스크롤

스타일 검증 중 발견한 별개 결함이다. 스타일 변경이 만든 것이 아니라 퀴즈 기능 자체의 문제이며, 같은 파일을 만지는 김에 함께 고쳤다.

퀴즈가 마운트되며 스크롤한 **뒤에** 위쪽 mermaid 다이어그램이 렌더되면서 콘텐츠가 늘어나 퀴즈를 아래로 밀어냈다. 다이어그램이 많은 글일수록 크게 어긋난다.

| 글 | 퀴즈 위 mermaid | 수정 전 | 수정 후 |
|----|----------------|--------|--------|
| 연말정산 | 1개 | 32px | 32px |
| QE·QT | 3개 | — | 32px |
| 연금저축 | 4개 | **458px** | 32px |

`ResizeObserver`로 문서 크기 변화마다 재조정하되, 휠·터치·키 입력이 들어오면 즉시 중단하고 3초 상한을 둔다. 자세한 근거는 선행 스펙의 "앵커" 절에 적었다.

## 6. 완료 기준

- 퀴즈 배경이 회색이 아니고, 글자가 본문과 같은 글꼴이다 (계산된 `font-family` 가 `ui-monospace` 가 아니다)
- 퀴즈 조상에 `<pre>` 가 없다
- mermaid 다이어그램은 이전과 동일하다 (여전히 `<pre>` 안, 회색 배경)
- 퀴즈 섹션이 앞 문단과 시각적으로 구분된다
- 보기에 마우스를 올리면 눈에 띄는 변화가 있다
- 다크 모드에서 문항 카드가 섹션 틴트와 구분되고, 모든 글자가 읽힌다
- 정답/오답 표시, `aria-disabled` 포커스 유지, `sr-only` "(정답)", `readOnly` 입력, 앵커 스크롤이 이전과 같이 동작한다
- 타입 에러가 기존 11건에서 늘지 않는다

**검증은 브라우저로 한다.** 이 사이트는 `layout.tsx:98` 의 `<ClientOnly>` 때문에 정적 HTML에 렌더 결과가 없어 빌드 산출물 grep 으로는 아무것도 확인할 수 없다.
